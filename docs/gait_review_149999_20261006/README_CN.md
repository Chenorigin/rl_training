# model_149999 上楼梯步态实测

## 结论

指定的 15cm 高、20cm 踏面、20级场景没有完成穿越。相同权重在仅将踏面改为30cm的对照中能够登顶，但仍没有学到“左前1→右前2→左前3”的步序：实际前、后腿均是左腿先上某阶、右腿随后上同一阶。窄踏面泛化与步序约束需要分别处理。

## 测试范围与方法

- 模型、权重、地形路径均使用用户指定文件，文件哈希见 [source_sha256.txt](source_sha256.txt)。checkpoint SHA256 为 `002ebb3c003a3924fe20d4bf0d18781a0fce60c050947c54c6cedb2e35828319`。
- 调用原 `deploy_mujoco.interactive_rollout()`，真实打开 MuJoCo 窗口；由测试脚本通过原终端按键路径发送 Z/C/W，保留趴下、起立、等待 ready、策略接管及动作混合逻辑。0.7m/s 为原 W 映射，0.5m/s 仅在对照进程中改变 W 的速度映射。
- Z 约在仿真0.26秒，C 约5.82秒，前进窗口6.5–28.5秒，之后停止并退出；最多1600控制步，摔倒即停止。物理200Hz、记录50Hz、视频10fps。视频起点约为仿真5.90秒，时间线以下均为仿真时间。
- 通过只读采集记录轮/髋位置、膝角、关节力矩、实际接触力、机身姿态与地形高度。录像是这次物理闭环的画面，不是静态关节姿态回放。
- 每个条件仅一次确定性测试。不能据此报告成功率或覆盖所有速度/地形。没有修改训练奖励、模型权重、原部署代码或原地形 XML。

首次 GUI 采集因录像分辨率超过模型帧缓冲上限而中断；仅将录像尺寸改为640×480后重跑相同条件。失败日志/残留数据完整保存在 scratch 目录，不作为任务性能案例。

## 1. 步序不满足相邻阶交替，左右存在固定先后偏置

30cm对照中前腿的稳定落脚序列：

| 仿真时间 | 腿 | 台阶 |
|---:|---|---:|
| 7.54s | 左前 | 1 |
| 7.82s | 右前 | 1 |
| 8.04s | 左前 | 2 |
| 8.30s | 右前 | 2 |
| 8.38s | 左前 | 3 |
| 8.58s | 右前 | 3 |

后腿同样是左后1→右后1→左后2→右后2。左腿持续领阶，右腿追随；这满足了“左右交替动”，没有满足“左右轮流占据下一阶”。现有高水位相邻阶交替率在30cm案例中前后腿均为0，检查次数各19次。20cm案例还出现跳阶、重复触地和左右落脚级数差扩大。

### 统计与奖励门控的盲区

三个GUI案例的 `front_same_tread_events` 都为0，与上述先后同阶序列并不矛盾：这个指标要求两前轮**同时**稳定支撑在同一阶。30cm案例中两轮先后落在同一阶，却没有被当前指标统计为同时同阶支撑。

当前 `mdp/stair_ascent.py` 的 `front_pair/rear_pair` 也要求两轮同时满足接触与高度条件。这项惩罚不能完整覆盖“后一腿再次落到前一腿已落过的同一阶”的序列违规。其他交替奖励的实际激活和总收益还需要训练侧日志/数值回放验证，不能把这一次部署测试视为所有奖励项的完整审计。

建议优先改为按**真实落脚事件历史**判定：记录每轴上一有效落脚的腿和阶，下一落脚应为另一腿的相邻更高阶；重复同阶单独计数、去除触地抖动，顶部平台及暂停/转向按既定门控处理。保留同时同阶驻留成本作为辅助。

## 2. 窄踏面时前腿摆动过度折叠

- 0.7m/s：13.10秒左前 hipy→轮中心距离约0.180m，膝绝对角2.783rad（约159.5°）。截图见 [front_swing_fold_tread020.png](front_swing_fold_tread020.png)。
- 0.5m/s：15.88秒左前距离约0.182m，膝绝对角2.775rad。
- 在首次非轮部位碰撞之前、轮仍在课程宽度内的上楼段中，按“前轮接触合力小于5N”为不承重样本，0.7案例有72/344、0.5案例有98/514样本超出现有摆动软约束范围。
- 30cm对照对应极端摆动样本为0；其最小前腿摆动距离约0.236m、膝角2.421rad。

这里最明显的压缩发生在不承重/摆动阶段，不能把正常抬腿需要的膝关节弯曲全部惩罚。持续支撑的前轮样本较少，20cm的0.7案例按现有0.2秒门槛仅有2个腿×时刻样本，0.5案例仅16个；这些样本不足以证明支撑姿态已经稳定解决。部署计时器与训练接触传感器计时器的细节不同，不直接把这一计数等同于训练奖励激活次数。

## 3. 横向漂移和偏航积累导致侧边失稳

0.7m/s命令全程没有横移或转向分量，但在13.10秒机身已到 x=2.269m、y=-1.558m；13.82秒首次有轮中心越出半宽2m的侧界，随后下滑，16.38秒触发摔倒停止。

0.5m/s在最大前进位置处偏航约-45.5°；最终离开楼梯到达 y≈-7.72m的平面，仍未完成穿越。没有摔倒不代表任务成功。

30cm案例17.22秒所有轮越过出口，登顶前最大轮中心横向偏移为1.931m，尚在2m半宽内，因此不是绕过楼梯。登顶后平台段有短暂越过侧界（最大2.087m），最终位于课程宽度内；不能将“完成上楼”说成整个轨迹完全没有偏移。

固定左腿领阶与横向偏移相关，但这次测试没有证明因果。后续应查机体系横向速度、偏航速度误差和左右支撑/落脚差异。速度命令约束的是机体系速度与角速度，不能直接把“世界朝向保持不变”作为已有控制契约；若需要楼梯路线方向约束，应明确其定义。

## 4. 窄踏面伴随非轮部位撞阶和冲击

- 0.7m/s在12.44秒首次出现左后大腿/髋段撞地形，记录峰值约1023N；13.10秒右后大腿/髋段碰撞记录峰值约3059N。随后有后膝、前腿和机身碰撞。
- 0.5m/s在15.90秒开始出现右前膝部撞阶，记录峰值约273N。
- 30cm对照未检测到超过1N的非轮部位与地形接触。

以上力是50Hz采样的MuJoCo接触力，不是实机测量，也不是电池能耗。其数值受当前MJCF接触参数影响，不据此给出真机安全结论。0.7案例后半段的跌落冲击不能混入正常上楼能耗比较。

## 地形分布差异与下一步优先级

该权重保存的 `params/env.yaml` 中上/下楼梯 `step_width=0.3`，训练地块8×8m、中心平台3m；指定测试是20cm踏面、连续20级直楼梯。30cm对照成功支持“踏面宽度是此次失败的重要影响因素”，不能据单次成功排除长度、初态及其他因素。

建议顺序：

1. 修正落脚序列判定与TensorBoard指标，使先后同阶不能被同时接触门控漏掉。
2. 扩展训练踏面宽度及连续阶数；同时记录不同尺寸的任务完成和横向偏移。
3. 对窄踏面时的极端摆动折叠与非轮碰撞作局部约束，结合已有前腿折叠项调节，避免所有膝弯曲都受罚。
4. 量化左右落脚/支撑偏置，检查横向及偏航跟踪；不要只用最终是否站着判断质量。
