# M20 CTS：全地形训练与楼梯专精

任务为 `Rough-Deeprobotics-M20-CTS`，入口为
`scripts/reinforcement_learning/rsl_rl/train_cts.py`。当前版本为
`m20_cts_action_latent_v16`。长期训练由用户启动；资源预检和有界仿真验证不进行优化器更新。

## v16 教师全网络训练

本版只改变教师可训练范围和优化器学习率分组，沿用 v15 的课程、奖励、限位、感知与学生结构。
`configs/distillation/cts.json` 的 `algorithm.train_teacher_base=true` 解冻教师全部基础 MLP 层；
基础、残差、安全及静止网络共同使用 `algorithm.teacher_learning_rate`。
共享解码器和 critic 使用 `algorithm.learning_rate`，学生使用 `algorithm.student_learning_rate`。
数值以该 JSON 为唯一台账，启动资源报告和 TensorBoard 会记录教师的实际学习率。

冻结的 `reference_teacher` 继续用于旧能力约束，探索噪声参数不属于本次解冻范围。
旧版 checkpoint 缺少这两个新增配置项时，加载仍保留原冻结语义及原推理结果。
新增版本没有加入前述墙课程改造或新的奖励；解冻的实际训练收益尚待验证。

## 复合指令与逐轴跟踪

默认配置 `all_terrain.compound_commands.enabled=true`。一般运动地形（motion、rough、blocks、pits、mixed）由 11 模式扩为 19 模式：保留原单轴/空闲模式，补齐前后走＋左右侧移、左右侧移＋左右转向，覆盖 WASDQE 的全部 12 个非相消两键组合。相消命令仍是零目标，不单设奖励。

新增节的速度区间覆盖当前键盘全幅：前后速度上限 0.7 m/s、侧移 0.5 m/s、转向 0.6 rad/s。前后走转向取消原来的半幅转速。每个分量分别采样，含小分量、半幅和全幅附近；所有数值以 `configs/distillation/cts.json` 为准。原楼梯、专门直行和平台课程沿用其速度与停止语义。

复合模式混合固定双轴与“单轴→双轴→单轴”的加减指令；先给哪一轴每回合独立随机，与左右符号无关。沿用平滑/突变抽样。组合持续时间按平面速度和配置的保守行程计算，并预留整机旋转足迹和边界余量；移动后重新查询实际地形支撑高度。限制的是采样路径，不裁剪策略输出，也不放宽限位失败条件。

跟踪目标对各轴计算 `(实际速度-指令)/sigma`，激活轴的 sigma 为相对容差乘指令幅度与原绝对下限的较大者；未激活轴保留旧的零目标漂移方差。取最大归一化平方误差后做 `exp(-error)`，同时作用于原 linear/yaw 两个奖励预算，权重总额不增加。这样不能靠某一轴跟得好掩盖另一轴完全不跟。零指令和楼梯/直行/平台使用原目标；姿态、限位、地图扰动、后腿上阶项继续生效。

课程成功判定也逐轴检查 RMS，容差使用实际斜坡及加减轴序列的指令 RMS、已有相对容差/绝对上下限；未激活轴沿用原绝对上限。各模式记录 `vx/vy/wz_tracking_rms`，避免低幅侧移被总平面误差掩盖。

对照时将整个新增节保留并设置 `enabled=false`，或读取不含该节的旧保存配置，恢复原 11 模式、奖励和随机数路径。加入新目标应使用 `--init-cts` 开新 run；旧 run 的完整 `--resume` 不会自动升级。软件接线和有界零更新验证不能证明新策略收益；需要新训练权重再跑组合矩阵、楼梯和实机验收。证据在 `logs/evaluation/cts_v15_compound_20261029/`。

## 软件关节限位

唯一数值配置为 [cts.json](../configs/distillation/cts.json) 的 `joint_limits`。
按关节名对齐 SDK 修正坐标下的目标角/反馈角边界、默认角和 action scale；
轮关节使用速度控制，不套腿部位置限位。感知与地图参数不因本次限位修改而改变。

训练在发出的 nominal target、每个物理子步的落脚修正目标与反馈位置上检查限位。
越限锁存至该回合重置，执行器在延迟队列之后覆盖为阻尼输出，回合按失败终止；
与超时同时发生也按真实终止处理。接近边界的余量代价覆盖楼梯和非楼梯；
学生蒸馏对完整输出目标加入可微代价，梯度通过冻结的共享解码器传回学生。
相关统计写入 `CTSJointLimits/*`，终止帧的日志在自动 reset 后仍保留。
原非楼梯旧关节余量项在新监控生效时停用，避免重复惩罚。

CTS MuJoCo 的 headless 和 viewer 都启用相同位置检查，含动作延迟之前的发出目标。
viewer 的趴卧、起立、躺下与阻尼阶段仅更新接触反馈；策略接管前检查反馈位置，
接管后每个物理子步执行限位检查。手动启动姿态不触发策略执行器的门控。
启动核验 XML 物理范围与软件反馈边界。首个越限立即失败；有 `--output` 时
另写 `.limit_failure.json`，保存阶段、关节、目标/反馈值与边界。
旧 v14 checkpoint 播放时也使用当前限位契约，因此可能暴露过去静默通过的动作。
不裁剪关节目标来掩盖越限。当前 SDK 的限位和软急停保持原配置。

有界接线验证（不更新权重）：

```bash

  --num-envs 256 --validate-only --validation-steps 8 --headless \
  --run-name cts_joint_limit_validation
```

v15 已接通相邻 `m20_student_deploy` 的离线导出入口，限位契约随 sidecar 保存并校验。
离线导出通过不代表新策略完成训练或实机验收。

## 地图过期与稀疏恢复训练

唯一数值配置为 [cts.json](../configs/distillation/cts.json) 的 `map_recovery`。
新 run 默认启用；每回合独立抽取是否加入扰动，覆盖全地形中的教师/学生环境，
不依赖地形类别或指令方向。被选中的回合在随机间隔后暂停有效采集，持续时间
超过当前地图 TTL，然后以少量新格恢复；恢复阶段随机采用保持稀疏后整体恢复，
或逐渐增加采集覆盖率。未选中的回合继续使用原感知扰动。

扰动发生在采集端：旧格保留原时间戳并自然过期，新格继续经过原包延迟、
高度噪声与质量/年龄置信度计算。没有延长 TTL、凭空提高有效性/置信度或插值
策略输入。稀疏化前先按完整地形计算遮挡，避免删除遮挡物后错误看见其背面。
这只是已有高度图传感器代理的时序扩展，不是实机 LiDAR/mapper 的完整复刻。

输入仍为原来的 789 维；关节限位失败判据与损失权重保持不变。此次没有增加
动作平滑损失、墙壁分类/障碍距离通道，也没有修改 MuJoCo 或 SDK 的运行逻辑。
已有权重不会因源码变更获得恢复能力；默认扰动范围是初始训练覆盖设置，
不是已经验证的最优参数，收益和楼梯能力保留仍需新训练后的对照评测。

`CTSMapRecovery/*` 记录选中比例、当前断流/恢复比例、全空比例、新有效格比例、
事件累计数及空图到有效图的转换累计数。最后一项也包含启动首次出图，不能单独
当作“成功恢复”；须结合事件数和回合结果解读。零更新验证报告也保存此统计。
资源预检将额外采集/遮挡工作区单列为 `map_recovery_reserve_bytes`。

可通过 `--config` 指定 `{"map_recovery":{"enabled":false}}` 做对照；关闭时观测、
原队列和随机数状态与旧实现一致。添加此功能前保存的 v15 checkpoint 仍可加载
部署；要采用新训练设置必须使用 `--init-cts`。即使版本同为 v15，旧源码的
checkpoint 也不能绕过源码哈希检查直接 `--resume`。

## 后腿上阶余量奖励

唯一数值台账为 [cts.json](../configs/distillation/cts.json) 的
`all_terrain.hind_clearance`；新 run 默认启用。`configure_all_terrain` 将以下三项
直接注册到原 RewardManager，教师和学生环境都执行同一物理目标；CTS 的教师 PPO
与原学生蒸馏路径保持原算法。TensorBoard 的 `Episode_Reward/hind_*` 显示各项
独立的回合平均贡献，不能把较高奖励当作已经改善上楼成功率。

- `hind_step_clearance`：依据真实碰撞地形的每个上升阶沿，计算轮子完整包络底面。
  在轮子前缘接近阶沿之前平滑提高目标，要求在越沿前达到踏面高度加余量。
  代价为有界的归一化欠高平方；贴地顶阶也计入，不允许用“不进入摆动”逃避。
- `hind_riser_contact`：在阶沿附近、轮子仍低于踏面时，惩罚反向纵向接触力。
  这是结合几何的顶阶力代理，净力不能精确区分每个接触点，不称为踢面碰撞标签。
- `hind_support_transfer`：后轮正在处理上升阶沿时，惩罚两只后轮同时失去有效支撑。
  单后腿抬起、另一后腿承重不会产生此代价；不指定对角相位或固定关节角。

目标只用于前进上阶，包括完整往返路线的上行段；平地、下阶、停车和后退不加这三项。
一只轮子在当前踏面落稳后，该阶沿从候选中排除，下一阶仍会被查询，短踏面不会因为
当前阶沿仍与轮子重叠而晚抬脚。尚未越过的阶沿则保留至完整包络越过，防止中心越沿后
目标过早切换。高于目标不再增加收益，原能耗、动作变化、冲击和软件关节限位仍生效。
目标使用训练特权几何，不把真实地形泄漏到学生输入或部署端。

部署模型的轮子为 cylinder，训练轮子为 capsule。测量工具分别报告真实 cylinder
包络和训练 capsule 包络，使用每个物理子步的独立运动学副本与真实接触求解结果。
“轮子最低点在首次前缘越沿时低于顶面”说明提前净空不足，但不直接证明发生碰撞：
圆轮可能沿阶沿滚上去。也不能据此认定电机力矩不足；实机仍需目标/反馈、执行器和接触记录。

可重复有界诊断（不更新权重，软件越限立即停止并保留此前样本）：

```bash
python scripts/tools/evaluate_cts_stair_clearance.py \
  --checkpoint logs/rsl_rl/deeprobotics_m20_cts/2026-10-29_13-52-43_651779_cts_motion_stability_v14/model_1500.pt \
  --model /absolute/path/to/M20.xml \
  --output logs/evaluation/cts_clearance_new_case --steps 1200
```

输出 `clearance.json`、`wheel_telemetry.npz`；`wheels` 为物理 cylinder，
`training_capsule_wheels` 为训练包络。`effective_contact_friction` 是接触解算实际值，
不能仅用地形 XML 的 friction 推断。已有分析与验收收据在
`logs/evaluation/cts_v15_hind_clearance_20261029/`。本轮只验证奖励接线和旧权重的现象，
未进行长期训练，未验证新奖励带来的仿真或实机改善。

已有 v15 checkpoint 不含此节时仍可部署。采用新奖励须使用上面的 `--init-cts`
创建新 run，不能用旧源码的 `--resume`；源码哈希门保留，既有训练进程不热加载。
对照可用 `--config` 覆盖整个 `all_terrain.hind_clearance` 字典并设置 `enabled=false`，
其余字段保持数值台账原值。当前 CLI 在顶层节内更新，不做更深层字段的递归合并。

## 课程分配与运动内容

[cts.json](../configs/distillation/cts.json) 是数值配置入口，当前课程分配由
`all_terrain.fractions` 控制。旧 `motion_practice` 等字段继续供兼容路径和部分
公共参数使用，不能用旧分组逻辑推算当前实际分配。

| 课程 | 全部环境的目标比例 | 主要内容 |
| --- | ---: | --- |
| 上楼梯 | 28% | 进入、连续上行、通过顶部并停稳 |
| 下楼梯 | 28% | 连续下行、到达落地区域并停稳 |
| 上楼—平台—下楼 | 14% | 完整路线与平台衔接 |
| 平地、斜坡、波浪综合运动 | 10% | 前后/左右运动、原地转向、弧线和转向切换、停车 |
| 随机粗糙地面 | 3% | 二维不规则起伏上的指令执行 |
| 散布凸起 | 3% | 随机尺寸与位置的障碍 |
| 浅坑与凹陷 | 2% | 真实下凹地形与支撑变化 |
| 混合地形 | 2% | 平地、坡段、粗糙面与凸起衔接 |
| 平地持续直行专项 | 5% | 持续前进与多余抬腿蒸馏约束 |
| 独立平台 | 5% | 台缘接近、较小落差跨下、高台停稳 |

楼梯合计 70%，非楼梯合计 30%。教师和学生保持固定的 3:1 环境群体；
各自采用最大余数法分配课程，预检报告取整后的真实数量。课程环境配额与
实际训练帧比例分别记录，不用重置次数代替训练量。

综合运动及新增地形覆盖前进、后退、左/右原地转向、前进左/右转弯、
后退左/右转弯、左右横移及零命令停站。左右分别抽样并使用独立课程账本。
弧线样本同时保留固定命令和“直行→原向转弯→反向转弯→直行”序列；
命令变化混合渐变与瞬变。回合包含等待、运动与停车阶段。
低速直线平移按所需地形暴露距离延长运动时长；原地转向、弧线和停站会布置在
实际起伏或障碍附近，避免小半径弧线始终停留在平坦出生区。
平台当前单独采用台缘接近或停站模式。
横移按自身目标距离计算运动时长；出生位置扣除轮足包络和所需行程，
成功同时要求身体中心与四轮中心的真实有符号位移。低速横移奖励使用相对
跟踪尺度，避免原固定尺度把不动评成接近满分；转向序列按实际指令能量
约束误差，避免直行段稀释“不转向”的失败。

## 接管初态与稳定性候选

数值仅以 `all_terrain.startup_stability` 和 `motion_stability` 为准。非楼梯
重置增加有界、左右对称的关节角和关节速度偏差，并裁在原软限位内；新增
实测滚转/俯仰角速度、静止轮速/腿速、静止动作跳变和关节限位余量代价。
运动中的横移/转向不使用静止腿速代价，保留必要抬腿；楼梯初态沿用原配置，
v15 的软件限位惩罚和失败条件也覆盖楼梯。

这只扩大训练初态覆盖，没有重现厂商站立控制器到 CTS 的真实交接过程。
实机执行器、接触支撑及零/非零命令分支切换仍需单独验证。原 temporal
辅助仍仅约束恒命令配对，命令过渡由在线课程和奖励覆盖。

## 连续采样与实际地形

楼梯高度覆盖 15–25 cm，踏面深度覆盖 15–35 cm。初始等级从已有能力范围
继续训练，后续依次扩展高度、较短踏面、较长梯段及较窄通道。
初始等级仍是楼梯训练，不加入低矮台阶的重新入门阶段。

地形库在 run 开始时，以保存的种子在连续区间内分层采样：当前为
10 类地形 × 7 个几何等级 × 每级 16 个样本，共 1120 个真实地块。
高度、深度、宽度、障碍尺寸和位置等采用连续取值；台阶数量和地形类别
属于离散结构。每个地块建成后保持静态，回合重置时选择相应等级内已有的
真实地块，不声称碰撞网格会每回合重新生成。
各等级在真实难度轴上连续分层，保证至少五分之一的样本进入难度边界区间；
坡面和波浪分别保证覆盖，避免冻结样本池缺少难例而永远无法满足晋级条件。

碰撞网格、射线、支撑高度/法线、出生点、边界和终点使用同一份几何。
凹陷没有被全局地面覆盖；完整往返楼梯留有平台和落地区域。
独立平台使用覆盖出生位置的抬高台面，避免把高台课程误建成单级高墙。

接触刚度、阻尼随地块在启动时连续采样；摩擦系数、动静摩擦比、质量/惯量
缩放、质心偏移和 PD 缩放在每回合重置时连续采样并作用到该环境的机器人。
材料通过物理接口直接赋值并回读，避免从几个预设材料桶中选择。
物理随机化同时影响教师和学生；DR 等级控制物理采样范围的扩展，感知的
噪声与延迟混合按保存的感知配置执行。
物理碰撞保留每地块单材质网格，使用显式碰撞分组保持环境隔离。
本任务关闭物理复制，以避免 env-ID 共享地形的全空间包围盒放大碰撞开销。
验收同时检查实际碰撞材质、射线高度和两群体的轮地接触力/净空支撑。

## 学生表现驱动的升降级

调度器按“地形类别 × 命令组”维护账本。命令组分为前进、后退（含后退弧线）、
原地转向、前进弧线、停站、左横移和右横移；楼梯与直行专项只使用其对应组。
教师和学生共享该组的几何/物理难度分布，教师成绩仅用于诊断。

只有当前版本、当前难度角色的已结束学生回合参与门控。
回合携带开始时的角色与版本，结束后只结算一次；旧版本、回放和挑战的成绩
不能帮助当前等级晋级或触发其降级。

| 条件 | 调度行为 |
| --- | --- |
| 连续两个互不重叠的窗口，每窗 100 个有效学生回合，成功率均不低于 90% | 晋升一个难度轴 |
| 每个晋级窗口同时覆盖至少 10 个难度边界回合、30 个延迟地图回合 | 才允许使用上述成功窗口晋级 |
| 连续两个有效窗口，成功率均低于 70% | 回退最近增加的一个难度轴；不要求覆盖条件 |
| 中间成功率、覆盖不足或样本不足 | 保持等级；完整中间窗口打断连续晋降证据 |
| 已到最高或最低等级 | 保持边界，不产生空等级或越出几何范围 |

几何与物理 DR 交替逐轴推进；一个轴达到上限后继续推进另一个轴。
回退恢复最近一次变化之前的等级，保持其他轴不变。
每次实际晋降更新版本并清空当前统计窗口，下一次重置才应用新分布。

`curriculum.max_window_updates` 当前为 30000 次策略更新。原因是占比仅 2%
的地形再按命令组划分后，较长回合与当前角色采样共同降低有效样本到达速度；
原 1000 次更新期限可能在凑齐一个窗口前就反复清空它。
本次延长的是证据的有效期，没有降低每窗回合数、成功率或覆盖门槛。
超期证据仍会清除，保存/恢复同时保存窗口、版本、等级历史及采样 RNG。

当前等级、历史已掌握等级、相邻挑战等级的目标采样比例为 60%/25%/15%。
刚开始没有回放池时，对应份额回流当前等级；达到最高等级后，空挑战池也
回流当前等级。回放只从有效历史等级取样，挑战只推进一个轴，三种角色的
证据通过回合角色标签隔离，回放与挑战不进入当前等级统计窗口。

楼梯成功要求四个轮足完整通过终点并完成稳定停车；未走完超时属于失败。
其他运动使用真实速度/转向跟踪和停稳条件，不能仅凭存活判成功。
低速命令采用相对跟踪阈值，避免“不动也算后退成功”。
平台按台缘风险、实际支撑和跨下/停稳分别判定，不套用普通地面的直行终点。

## 教师、学生与平地抬腿约束

v13 的教师动作输入契约使用干净的本体、地形和航向反馈；共享解码器的
教师公共输入也取干净教师观测。学生仍读取含噪声、缺测和延迟的感知输入。
教师与学生经历同样的物理随机化；“干净教师”不意味着机器人或执行器没有扰动。

学生额外地图投递延迟按回合独立选择：20% 为零额外延迟，80% 在保存的
延迟区间内连续抽取秒数，再安排到不早于请求时间的控制步交付。
这与 clean/regular/stress 噪声分组独立。零额外延迟仍有地图刷新周期、
抖动、缺测和其他感知误差，不能当作每个控制步都有无噪声新地图。
关闭新连续延迟开关的历史配置保留原整数步采样和随机数行为。

采集网格保留扩展支持域，最终模型仍接收原来的 187 点前视高程、有效位和
置信度。后方未知区域保持未知；复杂地形后退使用独立成绩与难度，不能把
教师额外可见的后方真值当作学生已经拥有的输入。

平地持续直行专项只在学生专项运动帧上增加解码后 12 个腿动作的蒸馏约束。
目标来自同一实际身体状态下的当前干净教师；车轮动作误差仅监控。
专项不会给楼梯或粗糙地面施加“必须贴地”的动作标签。
真实平地直行的离地/失撑代价也按地形和命令限定，保留复杂地形所需抬腿。

新零命令分支允许受限的腿部姿态修正；新增分支不输出轮动作修正。
教师基座仍冻结，教师残差、共享解码器与 critic 通过 PPO 更新，随后学生
编码器使用当前教师和辅助目标蒸馏。原教师在线动作约束在新地形上按配置
减弱；时序、空间及非前进保留目标继续使用各自的保存契约。

保留数据与原始命令收据位于
`deploy/models/cts/nonforward_retention_startup_20261027/`，属于运行输入，
不随文档清理。启动和恢复检查数据与配置；部署只依赖 checkpoint 内嵌契约。

## 观察训练与验收

TensorBoard 的 `CTSAllTerrain/*` 记录按教师/学生和地形划分的帧数、回合与
成功率，以及每个命令组的几何等级、DR 等级、版本和窗口状态。
`CTSAllTerrain/{teacher,student}/{course}/command/{mode}/*` 记录各命令的
帧数、完成回合、成功、速度误差、身体/轮组位移和失败原因。`CTSStability/*`
记录当前帧代价，不能把它当回合成功率。
`CTS/online_*_course_*_fraction` 用于检查实际优化批次的地形覆盖。
平地专项同时查看 `CTS/straight_leg_action_mse`、左前腿动作误差和
`CTSAllTerrain/{teacher,student}/straight/*` 的实测轮足净空、离地比例。
两个真实 rollout 群体不是逐帧同轨迹对照；只有专项动作标签在同一学生状态下查询教师。

有限 Isaac 接线验证可在预检命令上移除 `--preflight-only`，追加
`--validate-only --validation-steps 480`。此模式设置步数上限、不进行优化器
更新，检查实际地形/射线/材料、课程采样、保存恢复与部署导出。
当前正式日志和收据统一写入
[logs/evaluation/cts_allterrain_20261028/](../logs/evaluation/cts_allterrain_20261028/)。
以最终收据为准，不能把测试启动、短时存活或蒸馏损失下降当成性能验收完成。

以下为历史 v13 验证，不代替 v14：1600 环境 × 480 步、零优化器更新；十类课程的教师/学生均有
真实支撑，1120 个地块的物理材质检查通过，保存恢复及导出通过。
普通 CPU 回归 826 项与 48 个子测试通过；独立 USD 运行环境另通过 12 项材质/接线测试。

上楼、下楼、往返路线、其他地形各命令的通过率、跌倒、跟踪与停稳表现，
并检查平地左前腿多余抬高。课程和接线验证不代表已压制抬腿，也不代表
全地形能力或实机能力已经提升。

## 墙旁通行与门框转角

新增训练目标位于 `configs/distillation/cts.json` 的 `all_terrain.wall_practice`，默认启用。单墙、双侧通道、门框、前墙停车、左右转角均为真实碰撞墙体和平地；每类按净宽设课程，并随机出生横偏/小偏航。墙课程占 motion 课程中的一部分，保留无墙运动、全部楼梯、崎岖地面和平台任务。分配比例、宽度、速度、间距和代价参数以 JSON 为唯一数值台账。

训练使用路线生成原始速度指令：墙旁持续通行、前墙前减速停车、在足够宽的转角对正后再前进。该路线生成器使用训练场景参考路线，不是部署中的自主寻路器；学生仍只收原有 sensor789 与 raw-command3。墙仍进入高度/有效性/置信度图，不删除墙高程，不向学生塞场景真值标签。

全身安全代价覆盖现用 M20 的机身、腿和四轮物理原语；参考文件 `configs/distillation/m20_collision_envelope.json` 固定其来源与哈希。世界 AABB 有意保守，圆柱以胶囊包络覆盖 Isaac 轮碰撞形状；这是训练安全包络，不是接触力真值或实机间距认证。包络侵入过深记失败，未到终点不能以原地停止冒充成功。墙课程还使用平地抬轮/支撑成本和腿目标一阶、二阶变化成本，保留冲击、能耗、限位、后轮上阶和地图恢复目标。新墙域使用既有弱锚定，避免强制照抄旧模型的墙旁反应。

修改目标必须创建新 run。以下命令只作资源预检，不启动训练：

```bash
python scripts/reinforcement_learning/rsl_rl/train_cts.py \
  --init-cts logs/rsl_rl/deeprobotics_m20_cts/2026-10-29_13-52-43_651779_cts_motion_stability_v14/model_4500.pt \
  --num-envs 1024 --device cuda:0 --headless \
  --run-name cts_walls_v15 --preflight-only
```

用户确认资源余量后自行移除 `--preflight-only` 启动。旧 run 的 `--resume` 保留其保存的目标与严格源码检查，不会注入新增课程；旧 checkpoint 部署无需读取训练用碰撞包络 JSON，输入/输出维度不变。

正式软件回归、有限 Isaac 推理验证与未验证项见 `logs/evaluation/cts_v15_walls_20261029/report.md`。当前仅验证课程和控制接线；新策略的长期通过率、实际感知与实机效果需另行验收。
