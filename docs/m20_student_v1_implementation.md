# M20 学生蒸馏 v1 实现台账

授权范围：逐条实现上一轮蒸馏建议，交付可由用户启动的 v1。默认 618 维 MLP，从 v0 学生初始化；教师冻结。训练、Isaac/MuJoCo 闭环运行由用户启动。

参照：v0 代码、quiet_landing_v1 教师、既有三模型轻盈落地报告。不得以离线动作误差替代闭环效果。

1. 观测对齐：训练和部署共用传感器状态；固定前后视场、网格/高度/动作语义、地图时刻；各格历史有效性与过期。
2. 噪声：时序与强度解耦；空间相关高度、相对位置/航向漂移、相关姿态误差、持续缺测、本体观测、动作延迟；常态/轻噪/困难混合。
3. 质量：高度及相对位姿传播、边缘歧义、各格年龄；不得使用真值残差生成置信度；包含质量估计误差。
4. 蒸馏：新数据与新优化器、全学生执行终段、失败率调度门控、按阶段/地形/命令分层、关键状态保留、腿轮分组损失。
5. 记忆：默认单帧，提供可选本体历史并版本化额外输入；GRU/PPO 是后续由闭环证据触发的升级，不在默认 v1 中启用。
6. 验收：分因素与组合噪声、同条件模型对照、命令/通行/落地指标，用户自助入口。

冻结：v0 实现、部署行为、教师/学生 checkpoint、现有日志、PD 参数、轻盈落地奖励与物理 stepping。只为 v1 注册新 task；新增独立入口复用既有基础设施。

自验：CPU 单线程离线张量/解析几何、真实 checkpoint 初始化与导出对拍、版本及续训校验、离线采样/损失数值判据；不调用 runner.learn、不启动仿真或训练。仅编译通过是假阳性；小样本契约通过不能证明闭环收益。

资源依据：离线测试小批量模型和地图状态，预计 < 1 GiB RAM、单 CPU 线程、无 CUDA，新增代码与证据 < 10 MiB。开工实测可用 RAM 约 83 GiB、输出盘余量约 18 GiB；训练入口另做实时整机/整卡/磁盘预算。

既有结论：传感器表征应按地形语义对齐；只采简单地形会遗漏教师高档技能；干净与退化观测下的落地表现需要各自闭环验证。对应知识条目见 kb brief，相关旧项目条目不视为本项目已证实的问题。

验证记录：25 项 v1 CPU 离线检查和 8 项既有 v0 FOV 回归通过；实际 quiet_landing_v1 教师与最新 v0 的 model_29999.pt 完成权重初始化/JIT 对拍。默认 618 维动作与导出误差均为零。可选 789 维的 float64 初始化对拍误差约 1.71e-13，float32 因第一层 GEMM 宽度改变，随机测试输入最大动作差约 9.16e-5；JIT 对拍误差为零。没有优化器更新或物理步进。

独立复核：Codex reviewer 多次只读复核，并实际复跑小张量状态/历史/延迟检查。修正评测积分后 kinematics 滞后造成的观测时刻和距离误差，将地形等级接入真实采样键，并增加置信度成对参考。最后一轮未发现阻断。仅取得同 family 独立 reviewer，未取得异构 family；不声称异构复审已完成。

此次新坑按现象/真因/判据/修法记录：

- 现象：降低感知噪声时地图更新也变快；真因：原实现用同一 level 缩放误差和时间；判据：相同随机流下不同 level 的 capture/arrival/next_capture 应相等；修法：硬件时序独立于噪声强度。
- 现象：多次小位移后地图位置不变；真因：逐次最近邻重投影会抹掉亚格位移；判据：解析斜坡累计位移跨越半格后高程应改变；修法：保留原采集锚点，始终从原 packet 查询当前网格。
- 现象：评测每米触地能量偏低；真因：mj_step2 后原 xpos 比 qpos 落后一子步，混用前后 kinematics 会高估位移；判据：恒速一个策略步应只计入该策略步时间的位移；修法：同步 scratch 观测并累计相邻策略边界位置，保留原始已求解接触力。
- 现象：添加零权重历史后严格 float32 初始化相等判据失败；真因：第一层矩阵宽度变化改变累加顺序，真实大权重放大舍入误差；判据：严格权重/零列检查及 float64 动作对拍保持等价，float32 误差显式报告；修法：分开数学等价和有限精度容差，保留实际失败与复验记录。
- 现象：地图与重力使用同名 roll/pitch 误差却方向不一致；真因：点云向世界投影与重力向机身投影是相反旋转；判据：正 roll/pitch 误差满足 R_hat=R_true*Exp(tilt)，任意当前倾斜姿态下高程 Jacobian 与旋转有限差分相符；修法：地图使用同一个姿态扰动的一阶世界高程 Jacobian，投影重力减去 tilt×g，质量也传播对应 Jacobian。

## 4096 环境与 checkpoint 保存修正

- 现象：4096 环境被入口固定上限拒绝，默认输出预算远大于网络权重体积。
- 真因：人为环境上限与真实资源检查重叠；每个 checkpoint 同时重复保存普通和关键回放。
- 判据：4096/789 维配置可解析，续训仍拒绝改变环境数；真实序列化验证空回放底层 storage 为零；轻量保存不修改训练中的回放，恢复保留优化器和课程，完整模式及旧配置兼容。
- 修法：移除固定环境上限；新 run 默认 `save_replay=false`，完整回放保存可选；磁盘预算按保存模式计算，内存预算始终包括全部训练回放。轻量续训重新收集回放，并非原轨迹精确恢复。CPU 验证记录见 `m20_student_v1_4096_validation.json`；未启动仿真或训练。
