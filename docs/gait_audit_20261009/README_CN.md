## 两项奖励是否正确、有效

### 上楼方向惩罚

实现位置：mdp/stair_teacher.py `_ascent_direction_context`，约928–1048行。绑定权重-2已确认，训练统计非零；未发现左右符号反向或未接线。

它使用初遇楼梯时的参考航向，积分命令角速度与路径横向位移；机身自行偏航不会重置参考。成本是超过容差后的 `u²/(1+u²)`，横移容差10cm、尺度25cm，另加横向速度和航向误差。

生产函数实测：纯横移误差0.2/0.4/1/2/4m时未加权成本分别0.138/0.590/0.928/0.983/0.996。从1m偏到2m，加权成本只再恶化约0.109。因此它会处罚，但大偏移区分能力很弱；增大权重不能修复饱和曲线。路径参考和累计偏移是奖励内部历史状态，当前单帧观测未显式提供，也增加归因难度。

结论：实现有触发、符号正确；实测行为未被有效纠正。尚未逐帧将生产状态机在真实Isaac环境记录，因此不宣称整个楼梯期间门控覆盖100%，下坡过渡退出条件也需要后续单独记录。

### 下楼后腿前倾惩罚

实现位置：`_context`约1769–1883行、`descent_rear_forward_cost`约1995行。b为髋→轮心相对机身向下的前倾角；g为相对重力向下。与既有角度定义一致，不是膝角或大腿t。

只有下楼门控且命令vx>0.1、腿有向上支持力且未离地才处罚；两腿均值乘载荷增益clamp(Fz/60,0,1)。b阈值35°、g阈值25°，高台阶再放宽最多5°。因此摆动/非承重前倾不在约束中；多数承重姿态低于阈值也不处罚。

直接执行生产函数，合成b=g=49°，两后腿同载荷：
- 100N：未加权成本0.590；
- 15N：0.148；
- 6N：0.059；
- 0N：0。

数值见numeric.json。此处证明公式范围，不代表同载荷为MuJoCo真实轨迹。下楼最新模型承重b P95只有29.8°，仅由b判断仍未触发35°阈值；非承重P95约50.5°则完全不受该惩罚。因此很小的episode平均惩罚不等于姿态优美。

结论：角度方向及惩罚符号无明显算错，当前门控/阈值/载荷设计不足以满足用户对入口姿态与摆动姿态的要求。

## 后腿交替与因果边界

`ascent_state`约629–684行严格交替奖励要求单腿、安全跨越、相邻一级、左右正确，并且上一阶仍是单腿历史落脚；首落脚不发主要转换奖励。`stair_up_rear_step_completion`约1479行绑定该事件。避免同阶骗奖的逻辑成立，但目前后腿真转换极少，形成稀疏学习信号。与按整机跨阶独立发奖组合后，策略可以保持旧的同阶后腿模式完成任务，而不用学会指定风格。

“后腿同阶拖慢前腿”是合理假设，但单一轨迹同时存在大偏航，不能证明其为唯一原因。需要保持地形、命令、初始化一致的分支消融，分别改后腿引导/方向项，比较严格连续步数、后腿滞后时间与完成率；不能凭同时出现直接断定因果。

## 建议下一步（本轮未实施）

1. 方向项改为有界但在常见偏移范围仍保留区分度的分段线性/Huber成本，并更侧重即时横向速度与偏航；保留合法转向命令处理。记录激活占比和饱和占比，避免只加总权重。
2. 后腿前倾分承重与摆动两套软阈值；入口至最后后腿下阶全过程覆盖，允许必要摆动幅度；承重成本保留非零底系数，避免轻载使角度成本近乎消失。阈值须在入口实际角度轨迹与成功样本上确定，不能盲目将阈值压到零或绝对值处罚后伸。
3. 后腿交替补充目标下一阶的接近/安全抬轮/稳定落脚连续引导，最终仍只奖励真实相邻异侧转换，不奖励同阶补脚。引导使用势函数或完成后结算，防止原地抬腿、来回摆腿和重复落脚骗奖。不能直接猛烈放大稀疏违例惩罚。
