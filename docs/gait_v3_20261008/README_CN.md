## 一、为什么之前没有持续学会

### 1. 同阶与交替：奖励仪器先失明了

对10月7日22000模型已录制的15cm级高、30cm踏深上楼轨迹重新计算真实射线和生产奖励，发现：

- FR第2阶在8.94秒已稳定落地，旧目标直到9.32秒才处理；FL第3阶在9.40秒落地、9.76秒离开，而旧第3阶目标9.86秒才打开。登记晚于足到达，正确交替没有得到对应信用，早先落脚历史也丢失。
- 实际前腿5次、后腿7次同阶，10月7日状态机检出前腿0次、后腿7次；回退基线检出0次、4次。仅提高同阶惩罚权重不能修复漏记。
- 合成反例中，前腿漏掉第1阶后在第2阶支撑，后续100帧都无法更新目标；后腿同样会被第1阶队列卡住。
- 旧前腿每阶多个奖励叠加、后腿没有准备奖励，后腿目标又依赖前腿成功队列，激励与可获得反馈不对称。

新版真实轨迹复算能检出全部前5次、后7次同阶。这里改变的是奖励归因，原轨迹本身没有因此变成正确步态。

### 2. 前腿深折：真实承载被局部高程样点否决

在本轮开始时的回退基线上，保持100N竖直载荷、相同膝角及腿长，只让最近的187点高度落在低一级踏面，前腿cost由0.25变成0；初次20ms支撑也因接触时长豁免得到0。10月7日版本已去掉前腿初次接触豁免，但承载和摆动仍依赖局部地图有效性，不能把那一版的失败全部解释为接触豁免。地形栅格在台阶边缘跨层采样，仍会造成承载阶段错分或姿态约束失效。

此外，固定夹角与固定腿长不能随意同时收紧。本地官方MJCF前向运动学核验表明，大腿、小腿各25cm，髋到轮心还包含侧向偏置：a=90°时三维长度约38.7cm，a=55°时约28.0cm。[kinematic_envelopes.json](kinematic_envelopes.json) 保存实际结果。这只是关节范围及几何核验，不证明25cm台阶的整段严格交替动力学可达。

### 3. 下楼后腿前倾：腿长、膝角描述不了倾斜

后腿可以伸得很长，同时髋到轮心向前倾。原折叠惩罚无法直接约束这种姿态；只看机身坐标还会与机身俯仰混淆，入口短时载荷也容易被接触豁免过滤。

10月7日版本已经加入b/g前倾约束，不能说它完全没有这种奖励。追加旧版本函数回放发现：同一最新下楼入口30个坏样本在10月7日版本也全部被覆盖；其入口负积分约0.05362，新版约0.06788，增加约27%。因此这个真实场景的失败不能归为“全部漏罚”，还需调整与任务收益的关系并处理训练失稳；新版加入姿态对速度收益的有限折减，保留前进动机。[oct7_down_replay.json](oct7_down_replay.json) 保存反证。

旧下楼轨迹复算中，最新模型入口的30个承载前倾超限样本全部被新版rear_forward门控覆盖，角度重构误差小于0.000052°；其入口加权cost均值约为旧基线的2.5倍。说明新代价确实落在目标缺陷上，尚不能据此预测新训练结果。

### 4. 奖励以外的因素

[上一轮检测](../latest_gait_20261008/README_CN.md) 已记录10月7日训练后期动作std膨胀和value失稳；固定学习率不是稳定性的保证。当前PPO配置继承原仓库的adaptive日程，本轮未修改。

训练楼梯踏深固定30cm，原 `stairs_ascent.xml` 是20cm，存在分布差异。保持当前地形的本轮修正不能单独保证窄踏面的泛化；下一轮要分别评估匹配训练分布与原XML，不能混成一个“成功率”。

## 二、新的逐阶奖励记账

1. 从扫描中登记所有可见上行立面，保存世界位置、上下踏面高度、相邻关系及每条腿的稳定落脚历史。地形登记不依赖策略是否成功。
2. 前、后腿分别维护进度，允许任一侧先迈。之后要求换侧并落在相邻下一阶，例如FL1→FR2→FL3，HL1→HR2→HL3；首迈不强制左右锁步，两轴也不固定相位差。第一只脚只登记安全落脚并保留准备反馈，主要完成奖励从已证明的相邻换侧转换开始支付。
3. 脚必须越过扫描所能确定的立面区间，在有界踏面内形成连续竖直支撑。10cm点距不能提供精确立面位置，因此保存射线区间中的抬脚净空证据，并结合撞立面力检查；区间内初次接触不会提前消耗该阶信用。
4. 同一轴两只脚先后落同一中间阶也算同阶，即便首脚已离开；后续还会撤销该阶的严格交替指标。每轴每阶只计一次事件，前后同时发生则相加，另有累计停留惩罚。
5. 顶平台允许双脚支撑。判为中间阶需要观察到下一立面；尚未看见下一阶时无法证明顶平台身份，指标也明确依赖已观察地形。
6. 错侧、漏阶、未清缘不拿正确完成奖励，但以真实到达的踏面恢复后续目标，避免一次错误令后续奖励永久失明。已同阶的双脚状态允许任一侧重新开始，减少对无历史actor不可见的左右隐藏约束。
7. 前后各有一次性、带至少两足支撑的准备奖励，按抬高并前移的潜能增量支付。重复抬落、暂停、扫描变化和回访不能刷新预算；后腿无需等待前腿获得完成信用。
8. 横向扫描条带重叠时合并同一立面身份，防止横移后把同一台阶当作新楼梯重新赚钱。实际离开已观察楼梯邻域时关闭姿态阶段，保留历史；下楼阶段也限制在旧立面的轮足邻域，避免平地继续受罚。

主要变化的运行时权重为：前/后完成均+3，前/后准备均+0.5，前腿落地附加+0.25，交替附加+0.25，同阶事件−4.5，同阶停留−1。完成、前腿上行落地附加和交替附加共同使用新的转换事件，不在第一只脚首迈时预付。首次安全落脚仍可获得有界准备反馈和原有速度/前进收益。

事件函数返回事件量除以控制dt，Isaac RewardManager再乘dt，确保一次事件信用不随控制频率改变。`Episode_Reward`经过回合时长归一化，不能直接当作某一次落脚的信用。

## 三、姿态约束及预期动作顺序

### 前腿

定义a为膝铰平面内夹角 `180°−abs(q_knee)`；a越小越深折。

- 实际竖直承载后立即启用，按载荷大小加权；不再要求最近高程样点恰好位于脚下踏面，也没有初次接触免费窗口。
- 级高从15cm到25cm时，承载软下限从90°渐变到80°，摆动从75°渐变到55°；使用单调有界超量cost，并取夹角/腿长超量的较大值，避免重复收费。
- 前腿cost权重−3，新增前机身9点下包络垂直间隙cost权重−1。后者需要有效高度点，只是垂直净空代理，不是精确碰撞距离或立面水平间距。
- 姿态欠佳时最多折减原线速度跟踪奖励的25%，仍保留至少75%原跟踪奖励，避免抬腿时完全切断前进收益。原地停住也不会得到更大的准备信用。

预期上楼顺序：前脚由旧踏面抬起、适度弯膝清缘；在下一阶站稳时打开夹角并抬高前机身；另一前脚直接向下一更高阶迈进；后腿由自己的踏面历史交替跟进。允许摆动比承载更弯曲，允许高台阶适当放宽；不要求整段锁死角度。

### 后腿

定义b为髋→轮心向量相对机身−Z的前倾角，g为相对去偏航重力−Z的前倾角；正值表示向前。新增单侧超量cost，取b/g超量较大者，按实际承载加权，权重−2；15cm级高软界限为b35°、g25°，高台阶逐渐放宽。原后腿折叠/腿长约束保留，针对另一个自由度。

预期下楼顺序：前脚先转移到低一级踏面；后脚仍在高处支撑时，机身适当俯仰和前移，后腿保持合理长度与前倾范围；后脚卸载后再前送到低踏面。惩罚针对承载过度前倾，摆动前送及适当制动不被同一承载规则压住。

这是奖励所偏好的动作顺序，不是强制轨迹，也不是新模型实测表现。

## 四、TensorBoard重点指标

曲线在环境reset时由课程管理器汇总，不是逐帧角度波形。比例必须同时看样本量；没有楼梯样本时的0不能当作成功。

| 前缀 | 重点后缀 | 解释 |
| --- | --- | --- |
| `Curriculum/step_completion/` | `up_front_strict_coverage`、`up_rear_strict_coverage` | 已观察中间阶中满足安全、相邻、换侧且无后续同阶的比例；分母包括尚未到达的已观察阶 |
| 同上 | `up_front_longest_strict_run`、`up_rear_longest_strict_run` | 每环境保留下来的最长连续正确阶数，再取均值；后续同阶会使之前的阶失效 |
| 同上 | `up_front_six_step_strict_fraction`、`up_rear_six_step_strict_fraction` | 被汇总环境中具有连续至少6个正确中间阶的比例；不是完整楼梯成功率 |
| 同上 | `registered_risers`、`up_*_registered_intermediate_risers`、`up_*_landing_coverage` | 地形机会及真实落脚覆盖，防止只在少量成功样本上自报高比例 |
| 同上 | `up_*_same_tread_events`、`up_*_skipped_riser_events`、`up_*_unsafe_events` | 同阶、漏阶、未观察到安全越缘分别统计 |
| 同上 | `up_front_skip_fraction`、`up_rear_skip_fraction`、`up_*_physical_landings` | 跳阶首落事件数/物理首落事件数；一次跳过多个台阶仍算一次跳阶事件，必须同时看样本量 |
| 同上 | `up_front_same_tread_fraction`、`up_rear_same_tread_fraction`、`up_*_visited_intermediate_risers` | 已访问中间阶中曾被该轴双脚落脚的比例，包含先后同阶；顶平台不进入分母 |

| 同上 | `fl/fr/hl/hr_stable_treads`、`up_rear_lift_credit` | 四腿分别是否获得落脚与准备反馈 |
| `Curriculum/gait_quality/` | `front_loaded_a_mean_deg/min_deg/a_low_fraction` | 前腿承载角度与超量比例；摆动另有`front_swing_*` |
| 同上 | `fl/fr_loaded/swing_samples`及对应角度、比例 | 分左右腿，避免一条腿的均值掩盖另一条腿 |
| 同上 | `rear_forward_samples/excess_fraction`、`rear_body_b_mean_deg/max_deg`、`rear_gravity_g_mean_deg/max_deg` | 后腿实际承载前倾，均值和尾部最大值都观察 |
| 同上 | `hl/hr_forward_excess_fraction`及左右角度 | 左右后腿分别监控 |

| 同上 | `front_body_gap_samples/mean_m/low_fraction`、`loaded_without_local_map_samples` | 前机身间隙代理及局部地图盲区 |
| `Episode_Reward/` | 新`stair_rear_wheel_lift`、`stair_descent_rear_forward_cost`、`stair_ascent_front_body_clearance_cost`，以及已有前腿/同阶项 | 实际奖励贡献；绝对值变小需排除失去地形样本、停止和提前失败 |

## 六、追加：前腿跳阶、后腿双脚逐阶追赶

用户明确后腿顺序为HL1→HR1→HL2→HR2，前腿则有FL1→FR3的跳阶。这里要检查的是同一轴的落脚序列：正确FL1→FR2→FL3中，单独FL从1到3本来就跨两阶，不能简单限制每条腿一次只前进一阶，否则反而禁止正确动作。

随后用户进一步明确，前腿完整失败链是FL1→FR3跳阶后，两只前脚又追赶到同一阶。已补充生产函数连续反例FL1→FR3→FL3：FL1后，在第2阶可见的条件下目标为FR2；FR3记录跳阶且没有转换奖励，随后FL3记录同阶事件并实际产生同阶处罚，此段转换支付仍为0。不是只分别检查跳阶与同阶。出错后以实际第3阶支撑恢复，第4阶作新种子、第5阶合法换侧可再次支付，不要求机器人回退到漏过的第2阶。本次补测没有改变生产奖励源码。

### 为什么又调整支付时机

首次修正已经拒绝跳阶，并能在后脚晚落同阶时撤销严格资格、支付惩罚；但“先付首落奖励、以后再惩罚”的未折扣合计为负，不能证明PPO不获利。独立生产函数回放HL1 HR1 HL2 HR2 HL3 HR3，在首脚后等待0.6/1.0秒的两条固定序列中，完成+准备+同阶事件的折扣回报旧版为+0.355/+1.343。这里只计算选定风格项，并非整个策略回报，也不证明这是已有策略的唯一成因。

### 当前实现

- 当前落脚必须安全、单侧、与上一阶相邻并换侧；上一阶必须有安全单侧落脚记录，且当帧或历史没有该轴双脚同阶。满足后才支付主要完成奖励。
- 每段楼梯第一只脚只作种子，不预付主要完成奖励；前腿上行落地附加与交替附加也同步改用转换事件。原速度收益和有界准备反馈继续提供起步动机。
- 后轴独立判定，不等待前轴成功，也不强制两轴固定左右相位。犯错后用真实踏面继续记账：跳阶后允许下一安全相邻换侧恢复；同阶之后的下一安全单侧落脚作新种子，再下一正确转换可领奖。
- 不靠简单增加惩罚权重。本次没有再改变前腿a角、后腿b/g角参数、输入输出、速度采样、地形和PPO配置。

同一独立折扣回放两种等待时间的选定风格项改为−5.684/−3.925。消除了这两条“逐阶双脚追赶”的主要奖励预付收益，不保证任意延迟、任意动作和整个折扣回报都无法被利用：已经领取合法转换奖励后很晚才补脚到旧阶，仍可能留下折扣空间。实际训练必须同时检查同阶比例、连续严格阶数、完成率和采样量，不能只看完成奖励均值。

“后腿拖累前腿”的解释在力学上合理，但本轮没有做因果消融证明；不据此加入前后腿硬锁步。新支付规则能否让探索持续并形成目标步态，需要新训练验证。
