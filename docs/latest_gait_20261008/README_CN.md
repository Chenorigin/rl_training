# 最新 gait_safety_v2 模型效果检测（2026-10-08）

## 结论

**当前固定的22000权重不能替代196600基线：前腿姿态局部改善，但窄踏面登楼失败，下楼后腿前倾加重，严格交替仍未学会，机械功耗和常见轮端接触力没有降低。**

本次检测对象是检测开始时的最新完整权重：

`logs/rsl_rl/deeprobotics_m20_stair_teacher/2026-10-07_23-47-00_gait_safety_v2/model_22000.pt`

对照为`2026-10-06_22-06-56_stair_resume/model_196600.pt`。本轮迭代号从0重新计数，不能直接与旧196600相减。训练仍在继续，本报告不自动套用到后续新保存的权重。两个权重均复制后核验SHA256；详细身份见[checkpoints.json](checkpoints.json)。

## 测量方式

- 使用同一官方M20.xml、同一部署Actor/观测244维/动作16维/PD控制与原始趴下→Z站立→C策略FSM。Z在0.25s、C在5.8s、运动命令在6.5s；实际执行MuJoCo物理积分与策略闭环，不是摆姿态回放。
- 展示窗口用空viewer替代，推理单线程CPU，未使用训练GPU。只增加测量辅助脚本及本报告，没有修改训练奖励、配置、部署文件，也没有启停用户训练。
- 每个模型测3种楼梯和Q/E原地转向，共10个确定性回合；另对最新窄踏面测试做1次同条件继续运行，核实首次越界是否会恢复。**这不是随机种子成功率或全地形验收。**
- 几何在复制的MjData上重新计算，接触力读取原物理状态，避免更新实时几何缓存改变下一次Actor输入。续跑与原测试前368个记录帧逐字段完全相同。
- 接触力200Hz；姿态/落阶50Hz。站立总轮端力与机器人重力之比为约1.00018，10个回合均通过仪器尺度校验；交替判据用正确、同阶错误序列各自自证。
- 原始判据见[criteria.md](criteria.md)，在实验前冻结；补测判据见[continuation_criteria.md](continuation_criteria.md)。源码哈希在[source_hashes.json](source_hashes.json)，结束时核实全部未变。

## 1. 任务能力

所有楼梯级高15cm；30cm测试使用8级，原版XML使用20级。20cm踏面命令前进0.7m/s，30cm踏面前进0.5m/s。四轮越过出口且在路线内，无原部署程序摔倒，才算指定路线穿越。

| 固定场景 | 196600 | 最新22000 |
|---|---|---|
| 原版stairs_ascent.xml：20cm踏面、20级上楼 | 完成 | 首次轮心越界；继续运行后摔倒，未登顶 |
| 30cm踏面、8级上楼 | 完成 | 完成 |
| 30cm踏面、8级下楼 | 完成 | 完成 |
| 平地Q/E转向，各9.5秒持续命令 | 两方向未摔倒 | 两方向未摔倒 |

窄楼梯首次终止时，最新机身中心约(x,y)=(2.25,1.48)m，左前轮心y=2.001m，越过楼梯侧界y=2m。仅凭这1mm首次越界不能证明后续一定失败，因此补测保留越界记录但不提前停；最终原程序在总仿真时间19.32s判摔，Rzz=0.318低于原阈值0.35，未完成20级。原测试和补测数值分开保存，没有替换或放宽既有成功标准。

训练地形踏深固定30cm，20cm部署场景存在分布差异；这能解释窄楼梯的泛化风险，但不能解释30cm下楼后腿姿态也退化。因此不能把所有问题归到地形差异。

## 2. 前腿夹角a和前机身净空

a为膝铰平面内夹角`180°−|q_knee|`，越小越深折。前腿数据排除平地和顶平台；承载、连续承载至少0.20s、离地摆动分开统计。P5表示最低5%附近的角度，反映深折尾部，不是均值。

以下来自两版都完整完成的30cm上楼测试：

| 指标 | 196600 | 最新22000 |
|---|---:|---:|
| 承载前腿a的P5 | 71.3° | **92.3°** |
| 连续承载≥0.20s时a的P5 | 87.6° | **94.9°** |
| 摆动前腿a的P5 | 47.2° | **60.5°** |
| 摆动前腿最小a | 44.9° | 58.3° |
| 前机身下包络最小垂直净空 | 24.7cm | **29.4cm** |

**承载前腿和机身净空确有改善，但摆动仍有深折。** 在15cm级高的测试条件下，摆动角度仍低于配置中的软偏好，不能称为已经彻底修正。

窄楼梯初段也有改善，但补测继续失稳后，前腿摆动最小a降到12.9°，说明它并未泛化为整段稳定姿态。窄楼梯主测试提前结束，不能直接拿其部分路程的净空/能耗与基线完整20级做整体收益比较。

净空为9点机身下包络的垂直高度差代理，不是精确碰撞距离，也不是前机身到台阶立面的水平距离。

## 3. 下楼后腿前倾和弯曲

入口窗口为第一只前轮下降至第一只后轮下降后1秒；只统计连续竖直承载≥0.12s的后腿。b相对机身−Z，g相对去偏航后的重力−Z；正方向表示髋→轮心向前倾。

| 30cm下楼入口指标 | 196600 | 最新22000 |
|---|---:|---:|
| b的P95 | 36.0° | **43.2°** |
| g的P95 | 23.5° | **34.3°** |
| 髋到轮心最短距离 | 40.7cm | **29.7cm** |
| 后膝最大折角\|q\| | 82.8° | **119.7°** |

最新入口27.8%的上述承载样本至少超出b/g一个软偏好，b最大48.6°、g最大39.6°。**前倾和深折均出现退化**，即使最终能下完楼梯。

TensorBoard汇总的后腿平均角度包含整个下楼过程，向后摆时有负角，且混合大量普通姿态，不能替代入口窗口的P95或超量率。

## 4. 前后腿是否严格交替上楼

记录各腿每个中间踏面的首次稳定落地（持续至少0.06s），按时间排成前轴/后轴序列。目标为FL1→FR2→FL3…和HL1→HR2→HL3…，首迈左右均可；两腿先后落在同一阶也计为同阶，不只检查同时站同阶。

最新30cm测试：

- 前腿：`FL1 → FR2 → FL3 → FR3 → FL4 → FR4 → FL5 → FR5 → FL6 → FR6 → FL7 → FR7`。
- 后腿：`HL1 → HR1 → HL2 → HR2 → HL3 → HR3 → HL4 → HR4 → HL5 → HR5 → HL6 → HR6 → HL7 → HR7`。
- 前腿开头达到预期，之后恢复为同阶跟随；5次相邻同阶，正确换侧且逐阶前进的相邻转换6/11。
- 后腿仍有7次相邻同阶，正确转换6/13。这里的转换比例**不是整段交替成功率**。
- 基线30cm前后腿各7次相邻同阶；最新前腿略改善，后腿没有改善。两版均不满足整段严格交替。

窄踏面还出现漏阶/同腿连续落阶，详情在原始summary及[comparison.json](comparison.json)。顶部平台和起步平地不作为同阶违规。

## 5. 轮端力与机械能耗

只比较两版都完成的同一30cm路线。轮端合力取所有有载接触样本的分位；能量为`∫Σ|τ·qdot|dt/前进距离`，包括腿和轮关节。它是机械做功代理，**不是电池耗电或电机热损耗测量**。

| 指标 | 196600 | 最新22000 | 变化 |
|---|---:|---:|---:|
| 上楼轮端力P95 | 274N | 313N | +14.3% |
| 下楼轮端力P95 | 214N | 246N | +15.1% |
| 上楼机械能耗/距离 | 437J/m | 501J/m | +14.7% |
| 下楼机械能耗/距离 | 250J/m | 278J/m | +11.2% |

下楼单次最大冲击略下降（1526→1480N），但P95/P99更高；不能挑峰值改善来声称整体接触力下降。**目前没有证据表明这轮节能/低力目标取得实际收益。**

## 7. TensorBoard：局部改善与两次失稳

读取当前事件文件完整记录，核验TFRecord CRC，只纳入迭代≤22000的标量；末尾500轮统计如下。完整解析结果含每1000轮均值与极值，在[tensorboard.json](tensorboard.json)。

- 末500轮平均reward约107.68，回合长度996.47/1000，总terrain level约5.90，已回到较稳定状态。
- 前腿承载平均a约83.55°、摆动平均a约72.08°。完整曲线显示相较开头确有改善，后期约在现有范围平台化；训练级高和软边界变化，不能用汇总均值单独判每帧合规。
- 已记录中间阶的前/后严格局部比例约34.3%/22.5%，平均记录踏面数每环境0.394/0.308。它们分母是已记录阶，既不是整段完成率，也不是所有真实台阶覆盖率。
- up_success_rate约49.9%，仍是首次单级目标信用比例，不是整段上楼成功率。
- 新同阶成本约−0.02526、前折成本−0.00634、后腿前倾成本−0.00122，说明这些项有进入训练日志；**日志非零只能证明被执行，不能证明策略满足约束**。全地形混合均值会稀释门控项，不能只按这些均值大小给奖励排序。

### 显著失稳

开头约1000–2000轮出现一段退化；约16000–17500轮再次出现更严重崩落：

- mean_reward在17067轮最低−5730.26；
- Policy/mean_std在17191轮最高3.428（目前末500轮约0.438）；
- Loss/entropy最高41.80，Loss/value最高243428；
- action_rate成本最低−22.36、action_smooth成本最低−193.76，与17067轮极低reward同轮；
- 17212轮平均回合长度降到13.3，课程均值一度到0，bad_orientation终止一度到1。

这些是真实训练失稳信号，不是正常地形课程缓慢波动。后来reward恢复，不能证明此前策略能力或步态完全恢复。

### 原因的证据强度

1. **已确认：任务/步态存在取舍。** 30cm登楼前腿变直，但后腿入口、同阶跟随和单位距离做功没有同时改善。奖励被调用不代表组合优化后的动作符合预期。
2. **已确认：PPO经历动作分布膨胀与回报崩落。** 本轮设置fixed学习率0.0002；本地rsl_rl实现只有schedule=adaptive才按KL调整学习率，当前不会触发该机制。Gaussian的log_std通过exp得到std，这段实现没有上界。仅凭这些不能证明哪一次具体更新触发崩溃，但需要先检查更新幅度/分布边界，而不是把失败全部归到缺少奖励。
3. **已确认：存在踏深训练/测试差异。** 训练30cm、关键部署测试20cm；前腿姿态优化没有保证窄踏面泛化。
4. **尚未证明：具体哪个奖励与哪个奖励冲突导致侧向漂移。** 需要针对同一旧轨迹拆解门控和条件奖励、检查偏航跟踪/支撑几何；本次未改奖励，也不凭相关性强行指定唯一根因。

## 建议

保留196600作为已验证任务基线，22000保留为前腿姿态改善的候选；**不建议把当前训练直接放大轮数作为解决上述问题的主要措施**。优先检查PPO分布/更新稳定性，再处理下楼入口后腿约束、同阶事件覆盖及奖励取舍，并让训练覆盖20–30cm踏深。以后每个候选必须先保住固定任务穿越，再比较分阶段角度、实际落阶序列和力/做功。

这轮没有白练：证实了前腿角度与净空项有可学习的效果，并定位了剩余退化；但它不是整体晋级版本。没有擅自停止当前训练或启动新训练。
