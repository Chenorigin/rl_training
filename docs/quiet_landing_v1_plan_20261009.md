## 目标与冻结边界

目标是在保留上下楼梯、上下平台的任务能力和原步态约束时，减小四轮足接触前的法向接近速度。接触速度和动能仅是机械冲击/噪声代理；M20 实际降噪效果要由后续实机录音验证。

SHA256：`19743a46229a2ba138716adb7f02dafa318684a2500d13c8107661279c217dd5`。

冻结 Actor 的 57D 本体信息 + 187D 高程图、原观测顺序/缩放/裁剪、Critic 接口、16D 动作、关节顺序、动作尺度、默认关节角、控制周期、固定 PD 控制方式、机器人碰撞模型、既有地形/速度分布/课程和步态安全约束。PD 参数随机化沿用 baseline，不引入策略可调增益。独立 run 保存全部新产物，不覆盖 baseline；不修改 Student 或实机部署接口。

本轮只新增本计划文件。实现时先保存工作树的相关源码快照与配置、哈希，不批量提交/覆盖现有大量未提交修改。`params/env.yaml` 能保存参数，但不能恢复 Python 奖励函数实现。

## 已核对的项目事实

1. baseline 保存配置为物理步长 0.005s、策略 decimation=4，即 200Hz 物理、50Hz 策略；腿部名义 PD 为 stiffness=80、damping=2，轮为 stiffness=0、damping=0.6。执行前仍需核对运行时值与随机化。
2. 已有 `stair_impact_cost`：首次接触门控 × 向下轮心速度超出自由速度阈值后的平方。现实现从奖励计算时刻读取 `body_lin_vel_w`，存在读到碰撞后速度的可能，需实际时序验证；不能直接认定它没有效果。
3. 已有腿部 `joint_acc_l2`，以及楼梯专用、归一化且有界的 `stair_joint_acceleration_cost`；已有动作一阶 `action_rate_l2` 和二阶 `action_smooth_l2`。V1 复用这些项，检查原始值、加权贡献、课程缩放和 reset 历史，不再同义叠加。
4. 已有按轮位置搜索高程点并计算轮底离地高度的 `_context`；其中包含真实接触力/接触时间，不能整段作为可部署的高程接触估计器。还应保留 `ground_valid`，避免其失效填充值被误读为触地。
5. 现有训练采用 `StairGuardedPPO`，包括低学习率、baseline anchor 和 Critic 预热机制。新配置必须明确继承/配置这条路径，不能因 runner 子类的初始化分支而悄悄换回另一套 PPO。
6. MuJoCo 已有高程点显示、交互回放、固定命令回放和 NPZ 记录入口，可扩展。`draw_height_scan` 每次清空 `user_scn`，新增轮足标记必须与它统一绘制，不能画完又被覆盖。
7. checkpoint 文件时间为 2026-10-09 11:23；当前相关奖励源码下午仍有修改。时间差只能证明版本需核对，不证明该 checkpoint 使用了哪些修改。历史文档中的 214400/199998 数据不能代替本 baseline 的静音评测。

## 论文借鉴与轮足适配

原论文采用 aibo、开关式触地传感器、策略调节 PD 和课程训练，并以接触速度、关节加速度、机身角加速度辅助降低噪声。V1 只借鉴落地速度和运动平滑性，不宣称复现完整方案，也不直接照搬论文奖励权重。

原文：<https://arxiv.org/html/2502.10983v1>。

轮心正常滚动时存在水平速度，不能把轮心三维速度直接当作砸地程度。优先用法向接近速度；滚动滑移和台阶立面碰撞分开记录。

高程图预测的是几何接近，不能单独证明轮足已承重。V1 不新增接触观测到 Actor；训练奖励和验收可使用仿真接触真值，部署无需复制奖励计算。高程估计用于提前减速的软门控，并单独与接触真值校准，给 V3 留下依据。

## 信号、事件与奖励定义

每只轮足维护同一时间戳下的：轮心位置/线速度、角速度、局部地面高度/法向与有效性、轮底间隙、真实接触、估计接近状态、接触前速度缓存、事件编号和 reset 状态。按 FL/FR/HL/HR 明确排序。

### 主指标和主奖励

设有效地面法向为 n、轮足接触前速度为 v_pre、地面速度为 v_ground：

`s = max(0, -dot(v_pre - v_ground, n))`。

对水平踏面，n 为世界 Z 方向，s 对应下降速度。初版针对水平踏面；立面/边缘另统计，不能拿跨越上下台阶的拟合斜面冒充接触法向。后续若局部点来自同一连续表面，可扩展局部法向。

主成本：`C_td = sum_i new_contact_i * (s_i / v_ref)^2`，奖励为负权重乘该成本。`v_ref` 从 baseline 落地速度分布标定，记录为唯一配置；不靠任意大幅裁剪把严重冲击隐藏掉。

必须在每个物理子步更新速度缓存和接触事件；首次接触时使用接触前最近的无接触样本。先核对 IsaacLab 的 `step/update` 时序和速度所属帧，再选择环境子步 hook/扩展；只在 50Hz 奖励函数中缓存上一步不能保证得到最近的碰撞前速度。多个子步事件在一个策略步内累计，奖励与日志读取同一缓存且不重复消费；持续支撑不重复处罚，reset/出生支撑不生成伪落地。

事件应具备离地再武装与接触滞回/去抖。去抖只去重复计数；对真实弹跳保留原始接触边沿、反弹数和窗口内最大接近速度，避免漏掉二次砸地。

确认 RewardManager 是否对成本乘 `step_dt`，明确离散事件成本和连续窗口成本的尺度；单事件累计贡献应不随策略采样频率改变，不盲目套用同一个权重。

新主项在静音配置中替换旧 `stair_impact_cost`，避免重复处罚同一事件；其它既有奖励先原样保留。

### 高程接近窗口

用原始有效高程点、轮足 FK/姿态和轮碰撞几何计算间隙。轮心高度减半径只作为水平踏面的近似；倾斜/侧面接触要注明适用范围。不能对 Actor 已裁剪的高度值无说明地反解绝对高度，也不能加入额外完美射线后声称使用了原 187D 感知。

候选软窗口：在此前确实离地且向地面接近时，`C_pre = sum_i valid_i * airborne_est_i * w(clearance_i) * (s_i/v_ref)^2`。w 在接近地面时连续增大，离地抬腿与稳定支撑时关闭。

V1 首先实现并测量事件奖励。仅当事件项学习信号过稀疏，且高程窗口通过独立校准时，启用小权重 `C_pre` 做单独消融。地图缺失不制造触地或零误差结论；记录无效比例，主事件统计继续运行。平台下降后远离边缘也要覆盖真实落地，不能完全依赖瞬时“看见楼梯”的门控。

### 平滑项与动能

先只新增/修正落地主项；再单独评估适度增强腿部加速度或腿部动作平滑。保留轮速度动作的必要快速响应，避免统一增强 16D 平滑损害轮控制。先检查现有 action 二阶历史的 reset 与缩放，发现问题单独说明，不能把未验证修正混入静音收益。

动能默认记录 `specific_normal_energy = 0.5*s^2`，单位 J/kg；若乘轮刚体质量，明确名称为“轮质量法向动能代理”。这不是整条腿/整机接触有效质量，也不是声能。固定质量下与速度平方等价，V1 不再把动能重复加入奖励。三维轮心速度/动能可作诊断，但不作为唯一静音指标。

## TensorBoard 与 MuJoCo 交付

| 仪器 | 需要显示/保存的量 |
| --- | --- |
| TensorBoard `QuietLanding/` | 每轮、总体、上楼/下楼/上平台/下平台的接触前法向速度 mean/P50/P95/max，单位 m/s；比法向动能，单位 J/kg |
| TensorBoard 原始事件与覆盖 | touchdown_count、反弹数、有效地图比例、估计窗口覆盖率/误报率/漏报率、无效样本数、每米事件数、每米代理能量 |
| TensorBoard 奖励与约束 | 新成本原始值和加权贡献、既有加速度/平滑贡献；任务成功率及尝试数、速度跟踪、完成时间、停止/倒退比例、腿部碰撞、既有步态安全指标 |
| MuJoCo 实时画面 | 四轮分别显示离地/接近/支撑状态；落地瞬间闪烁标记及法向速度箭头；显示真实接触与估计状态的差异 |
| MuJoCo 数值/曲线 | 每轮间隙、接触前速度、最近事件能量、最近峰值；同步滚动曲线显示间隙/法向速度/接触状态与事件标线 |
| 离线产物 | 200Hz 信号 NPZ、带场景/seed/命令/checkpoint 哈希的事件 CSV/JSON、固定回放视频和四轮时间序列图 |

训练在线分位数采用有界样本缓冲/直方图并记录统计窗口；不对整个训练事件历史无界累积。零事件/无有效数据必须显示缺样本，不能写成“速度为 0 因此安静”。MuJoCo 的交互与固定命令回放都接上子步采集。启用可视化后仍保持控制时序；不加入假 dB 数字或合成音效。

实现建议落点：新 `mdp/quiet_landing.py` 管理信号与成本；独立 quiet V1 环境/runner 配置与 task 注册；最小子步采集接线；MuJoCo 新 `quiet_landing_metrics.py` 和现有 viewer/rollout 接线；专用静音评测脚本。配置共用权威参数台账，Torch 与 NumPy 实现用共同正反例对拍，不要求在 MuJoCo 导入 Isaac 运行环境。

续训使用指定 checkpoint 的完整恢复路径和单独冻结 Actor 参考；anchor 参考不能继续误指旧 199998。奖励改变后重新安排 Critic 预热，并验证 warmup 计数、训练起始迭代、环境课程状态与 checkpoint 恢复语义，不假设它们都会自动恢复。继承 baseline PPO 配置，仅修改已明示的静音项；先核对当前底本变更，不在 V1 同时改任务风格。

## 固定评测和采纳规则

覆盖上楼、下楼、上平台、下平台、入口/中段/出口/出口后平地；按高度、踏深、命令速度和初始条件分组，包括训练分布内和单独留出的组合；平地正常滚动为误罚对照。平台有独立场景和真实任务完成条件，不能只用楼梯顶面统计代替上下平台。

各候选同一场景、seed、命令、模型、PD、碰撞参数、时间预算和失败条件配对运行；至少保留未训练 baseline、当前奖励底本续训但不加入静音增量的控制组、事件奖励候选；平滑增强/高程窗口随后单变量比较。候选从同一 baseline 出发，不靠串行改权重掩盖历史差异。训练预算一致；以任务能力和物理指标选优，不以 total_reward 选优。

Q3 完成后、首个候选训练前，把数值门槛写入唯一 `criteria.json` 并冻结：各场景成功率/速度跟踪/完成时间允许退化范围、法向速度 P95 与每米代理能量最小改进、最小事件数/独立 episode 数、置信区间规则、失败与待定条件。现阶段不凭空指定“降噪百分比”。

采纳需要：各任务能力门槛通过；落地事件统计具有足够样本；总体及困难分组法向速度尾部/代理能量改善；没有靠停住、绕行、改变迈步模式、拖轮、跳阶、牺牲抬脚避障或减少统计事件获取收益。按 episode 聚合/重采样报告不确定性，不能把同一 episode 的每个子步当作独立试验。成功回合与全部尝试分别报，失败前冲击也不能删掉。

反例：速度变小但没有走完，是假阳性；只读碰撞后速度会漏检严重落地，是假阴性；高程边缘/遮挡误估让真落地漏算，需真实接触参考发现。对立面撞击单列指标和视频，法向踏面速度下降不能掩盖侧撞增加。

停止并交付计划/实验报告的条件：工作包产物和检查齐全，报告明确通过/失败/待定/跳过。V1 仿真通过仅支持“落地机械冲击代理改善”；实际声音待同地面、同速度、同麦克风位置的实机配对录音验证。
