## 结论

1. 后腿没有形成逐阶左右交替。固定 20 级、15 cm 高、30 cm 深上楼中，后腿为
   `HL1 -> HR1 -> HL2 -> HR2 -> ... -> HL20 -> HR20`，20 级全部被两条后腿先后占用。
2. 前腿也不是全程逐阶交替：开头为 `FL1 -> FR2`，从第 3 级开始恢复为两脚同阶。
3. 固定 5 级下楼中，模型完成且未摔，但首次入口发生真实前后腿自碰撞。最深记录为：
   左侧 `fl_hipy <-> hl_wheel` 穿入 1.66 mm，右侧 `fr_hipy <-> hr_wheel` 穿入 2.77 mm；
   同一窗口还出现前后轮互撞。
4. 与本 run 的恢复起点 `model_214700.pt` 相比，入口后腿平均前伸明显减小，但峰值几乎不变。
   说明奖励改善了主体分布，没有压住危险尾部。

## 根因

### 上楼

- 严格奖励只在完整的相邻、异侧、安全转换后支付；恢复奖励本来用于从同阶模式迈出第一步，但实际事件近乎零。
- 整机跨阶奖励与速度跟踪不要求后腿严格交替，同阶步态仍能持续获得主要回报。
- 前后轴的目标台账独立，未直接奖励“后腿相位与前腿相配合”。

### 下楼

- 本次训练配置明确 `enabled_self_collisions: false`。因此 Isaac 训练里前后腿可互穿，接触传感器与
  non-wheel contact/scrape 奖励也看不到这类自碰撞。
- 下楼奖励约束的是髋到轮心的 x、角度和腿长，不是前后腿碰撞几何间隙。平均姿态可改善，同时极端姿态仍撞腿。

## 建议的修正顺序（本轮未实施）

1. 先建立训练侧与 MuJoCo 一致的指定前后腿碰撞对/最小间隙量具；不要只盲开全身所有自碰撞。
2. 下楼入口成本直接约束前后腿碰撞几何间隙并覆盖到两后轮下层稳定支撑；继续保留 x/角度作为姿态项。
3. 上楼先做“同阶状态 -> 单后腿落到下一阶、伙伴留在原阶”的高访问率小课程，再进入长楼梯；恢复事件仍近零时不要只放大最终严格奖励。
4. 显式加入前后轴相位配合目标，并用逐腿逐阶历史验收，不能用每一级首个到达者冒充交替。
