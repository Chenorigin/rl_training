# 测试前冻结：149999 上楼梯步态检查

- 使用用户指定模型、权重与 stairs_ascent.xml，不修改奖励、策略或 XML。
- GUI 主测试使用原交互流程 Z→C→W；W 命令取部署中的 TELEOP_VELOCITIES。
- 较低速度对照先用已有 evaluate_stair_gait.py，匹配 XML 的高度/踏面/级数；初始站姿与 GUI 起立过程不同，须注明，不能把差异全归因于速度。
- 穿越：报告现有 crossed_finish / inside_course / fell；另检查完整轨迹是否离开课程宽度，不能只凭终点排除绕行。
- 步序：使用实际 XML 高度得到级数，记录左右前后轮稳定落脚；同轴两腿同阶支撑排除顶部平台。同阶事件数、驻留时间、交替率须同报，不能只用其中之一下结论。
- 腿部压缩：报告 hipy→wheel 距离及膝关节绝对角。支撑/摆动分别测量，软约束阈值与 grace 取当前 mdp/gait_refinement.py:TUNING；不将收腿正常摆动自动称为异常。
- 稳定性：机身 pitch/roll、轮地支撑力、非轮部位与静态地形接触、动作/力矩变化；合成稳定接触误判需查实际碰撞记录和截图。
- GUI 截图/视频必须来自该次物理闭环；不把静态重摆姿态当策略运行。
- 固定时长取 GUI 前进22秒后停止1秒；对照1250个50Hz控制步（25秒）。不因结果好坏改变已跑案例的条件。
- 已知度量边界：轮中心向下射线在台阶边缘可能读到相邻阶，不等于真正接触面；现有交替检测不证明抬腿腾空；全部失败、缺失项照实报告。
- 资源：串行1进程，主存预算3GB、显存1GB、磁盘产物预算100MB；本次开跑前主存约106GB可用、显存约48GB可用、磁盘70GB可用。短跑有界，不设长驻服务。
